# 提交后复核与修正

本补充发生于 2026-10-19 22:28（北京时间）初版 `7a74cc6` 提交之后。业务证据仍只来自 `data/render_jobs.csv`。外部 AI 审查提出了值得补充的问题，但其中的计算与推论仍需独立验证。

## 有效比例的完整最优区间

开发期 688 个任务、35 项候选保持不变，每条候选的净收益均为 α 的直线。比较全部交点得到：

| 区间内部    | 最优候选      | 净工时       |
| ----------- | ------------- | ------------ |
| 0 至 2/5    | 不拦截        | 0            |
| 2/5 至 5/12 | 同步 ≥30 分钟 | 8400α − 3360 |
| 5/12 至 4/9 | 同步 ≥25 分钟 | 9360α − 3760 |
| 4/9 至 1    | 同步 ≥20 分钟 | 9720α − 3920 |

相邻候选在三个切点上并列，按较少拦截分别选“不拦截”“≥30 分钟”“≥25 分钟”。两端 α=0、α=1 分别选不拦截、≥20 分钟。

因此，“α≥40.3% 时 20 分钟始终唯一最优”是错误的区间外推。α=40.3% 时，30 分钟为 +25.2 工时，25 分钟为 +12.08 工时，20 分钟为 −2.84 工时。20 分钟的开发期盈亏点约 40.33%，最优候选切换点约 44.44%，两者不是同一个问题。

这是固定历史样本、固定候选、统一 α 下的精确比较，不是总体最优性或因果证明，不能消除全量探索和候选选择带来的偏差。

## 团队差异按相同成本口径复核

| 分组         | 命中总数 | 已知失败 | 已知成功 | 未知 | α=50% 净工时 | 盈亏点 |
| ------------ | -------: | -------: | -------: | ---: | -----------: | -----: |
| 海外定制组   |       69 |       13 |       55 |    1 |         −600 | 88.46% |
| 其余三组合计 |      203 |       99 |       91 |   13 |         1880 | 34.18% |
| 全部         |      272 |      112 |      146 |   14 |         1280 | 40.48% |

原审查中的海外组 87.2%、−580 和其余组 32.0% 来自仅计算已知结果的口径。比较固定政策的全部成本时，未知任务同样需要扣 20 工时。

海外组 233 个任务中，69 个命中，68 个命中结果已知。该组已知失败率从 <20 分钟的 12/149 上升到 ≥20 分钟的 13/68。关联仍为正，但幅度较小，在统一 50% 假设下净收益为负。团队是组织分组，不等于客户数量，不能将四组中的三组概括为“四分之三的客户”。

当前不按这次探索直接制定团队阈值。风险差异不代表真实干预效果差异，需要检查任务类型、字段采集与实际修复结果。

| 观察                                        | 可以支持的结论                                 | 不能直接推出的结论                     |
| ------------------------------------------- | ---------------------------------------------- | -------------------------------------- |

| 复核期组合规则 2340 工时，高于固定规则 2200 | 两个时期的样本排序不同，保持原规则避免据此重选 | 差异已被证明是噪声                     |
| 当前网页提供提醒                            | 真实行为、成本和效果需要测量                   | 提醒成本必然低于题目给定的 20 工时     |

## 如何重算

```bash
npm run analyze:render
npm run verify:render
python3 scripts/verify_render.py
npm run check
```

`results/render-metrics.json` 的 `ruleSensitivity` 保存精确切点、区间与端点平局，`candidates` 保存开发期与复核期的全部候选计数，`byTeam`、`byScene`、`byDay` 保存组内两侧的分子分母及全部命中成本。Python 不导入 JavaScript 分析代码，独立重建候选，并用精确分数检查每个区间两端对全部候选的优势；线性差值两端非负即可保证整个区间非负。

原始 CSV、固定 20 分钟预检、957 个审计任务和 272 个命中任务未改变。实际有效比例、真实成本、字段快照语义和跨时期稳定性仍需要业务验证。
